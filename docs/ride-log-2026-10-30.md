# Ride log 2026-10-30 (first test with ola-dash as home)

Source: `tmp/ride-logs/` (calls-*.log, can-*.log pulled from
`/sdcard/Android/data/dev.olatool.dash/files/logs`). Short walk-speed test:
unlock, ignition, mode cycling, reverse, Android Auto, lock. Max speed 2 km/h.

## Vehicle state machine (IVehicleModeCallbacks.onVehicleStateChanged)

| State | When |
|---|---|
| SLEEP | head unit idle, ECUs asleep (ECU mode SNA) |
| VEHICLE_IDLE | power-button wake while locked (ECU_POWERUP, passcode window opens) |
| PARK | unlocked, not ready (lock reason SSB_UNLOCKED, MCU supply on) |
| DRIVE | ready to ride: power button Normal_Press while PARK (ECU DRIVE_NORMAL) |

Power button (`IVehicleInfoCallbacks.isPowerButtonPressed`): Normal_Press toggles
PARK <-> DRIVE; Long_Press in PARK locks (LOCK_IN_PRGS, SSB_LOCKED, Vehicle_Locked).
"Ready" = `VehicleStates.DRIVE` (confirmed).

## Ride modes

Mode button (`IHandleBarCallbacks.onDpad_Drive_Mode`) short press cycles
NORMAL -> SPORT -> CUSTOM -> NORMAL. Each time the cycle reaches the Hyper slot the
vehicle sends `CommandFromVehicle.PRNTCNTRL_HYPER_ACS_REVOKED` and skips to CUSTOM
(Hyper disabled in the app's mode access settings).

| Source | Normal | Sport | Custom | 3 s hold (02:25:11) | Reverse |
|---|---|---|---|---|---|
| onVehicleDischargeModeChanged / onDriveModeChanged | NORMAL | SPORT | CUSTOM | LIMPHOME | PARK_ASSIST |
| onVehicleModeLevel4Changed | NORMAL | SPORT | CUSTOM | NORMAL | REVERSE |
| onECUModeChanged | DRIVE_NORMAL | DRIVE_NORMAL | DRIVE_NORMAL | LIMPHOME | (unchanged) |
| onRangeChanged (km) | 97 | 86 | 104 | 119 | - |

The 3 s hold is Eco (highest range, 119 km): Gen 1 reports Eco as LIMPHOME
(rider-confirmed).

Reverse: `isCruiseReverseMode` pulses true, then ModeLevel4 REVERSE / DriveMode
PARK_ASSIST; both indicator callbacks carry fault `REVERSE_MODE` while reversing.

## Speed, distance

- `IMotorInfoCallbacks.onSpeedChanged(int)` km/h (max 2) — the display value; used.
- `IMotorInfoCallbacks.onVehicleSpeedChanged(float)` (max 2.1) — finer, same signal.
- `onVehicleDirectionChanged` 1/0 toggles with motion.
- `onDistanceCovered` stayed 0: not a trip meter. Trip must be computed from
  `IDisplayInfoCallbacks.onOdoValueChangedInMeters` (38198785 -> 38198788 m).

## Other useful signals seen

Battery: SOC 70 (display int) / onOverallSocChanged 70.4-70.5, onBatteryCurrent,
onBusVoltage ~54.6 V, temps, onPackSoH 100, onBMSModeUpdated
(Sleep/Standby/Discharge). Brakes front/rear, inclination, acceleration,
regen notifications, cruise availability, D-pad buttons, VIN, ECU versions.

## Host observations

- Keep-alive (this build): `true` from unlock (02:24:09) to lock (02:27:40). Changed
  afterwards to the stock rule: `true` only for the tick after a touch/key input.
- Each power-button wake recreates the activity, so logs split into a ~1 s session
  plus the real one. No leaked candump processes.

## Reverse vs Easy Park (second test, 03:02 and 03:14) — parked

Both entries (one short press of the cruise/reverse button) looked identical:
`isCruiseReverseMode` pulse, ModeLevel4 REVERSE, DriveMode PARK_ASSIST, indicator
fault REVERSE_MODE. `DriveModes.REVERSE` never appeared.

Raw CAN on entering reverse, same values both times: `0x115` 9001A0.. -> C20196..,
`0x143` byte1 0x24 -> 0x54, `0x353` byte6 0x04 -> 0x64, `0x683` 0002.. -> 0001..
Everything else that differed was motion (0x354 speed, 0x356 odo, cells/temps,
0x6C4 byte4 = 0x0A while moving).

Rider: plain reverse vs Easy Park is a setting in the stock HMI, not a different
button press, so both tests were probably the same mode. The setting is likely
`CommandFromHMI.Park_Assist_Enabled` (ordinal 103, frame 0x6BC) from the maintainer's
analysis of the stock HMI; not verified. Dash shows EASY PARK for PARK_ASSIST until the
plain-reverse signal is seen.

## Callback cadence per vehicle state

The parser re-broadcasts every value about 10 times a second, even at 0 km/h. "setNum-fed"
means the callbacks that write a Vehicle value (the ones `data-stale` watches); "any" is every
callback in the calls log.

| State | Span | Callbacks/s | Max gap, any | Max gap, setNum-fed |
|---|---|---|---|---|
| DRIVE | 163 s | 716 | 37 ms | 96 ms |
| PARK | 48 s | 710 | 22 ms | 93 ms |
| VEHICLE_IDLE | 130 s | 710 | 29 ms | 90 ms |
| SLEEP (head unit up) | 90 s | 601 | 72 ms | 95 ms |

Before the first state callback there is silence of up to 277 s, which is why the stale timeout
only runs in DRIVE. Session A's M-rate row confirms this at road speed.
